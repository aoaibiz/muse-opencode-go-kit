# ダッシュボードを作る

詳しい作り方は https://github.com/aoaibiz/muse-opencode-go-kit/blob/main/docs/DASHBOARD.md にあります。ここは着手と完成判定の要点です。

## 着手前

- 完成条件、合格の証拠、変えない物、例外の判断者を短く書きます。
- 関連するデザインの型（基本の設計スキル群）を、言われずに最初から適用します。後から足すのは却下の型です。

## 形の決まり

- 3階層にします：最初の画面はスクロールなしのメニュー、押すとカード式の一覧、タップで詳細。
- 状態の区分はタブ切り替えにします。縦に積んでスクロールさせる形は使いません。
- 更新は自動だけです。手動の更新ボタンは付けません。
- 表示する時刻は、そのデータが実際に保存された時刻にします。
- 全項目に実在の行き先へのリンクを持たせます。推測で URL を作りません。
- 絵文字はアイコン欄の1か所だけに持ちます。題や名前に埋め込むと画面で2個並びます。保存時と表示時の両方で題から取り除きます。
- 演出の光やグローは中心を画面の内側に置きます。端に乗ると実機で線が出ます。
- 長い文は省略で切らず、折り返して全文を見せます。

## 完成の確かめ

- 本番の実データを読み、件数・中身・更新時刻が想定どおりか確かめます。作り手のテスト用複製は本番の代わりになりません。
- スマホ幅（390）と PC 幅（1024／1280／1440以上）で、はみ出し・切れ・重なり・横スクロールが0であることを測ります。
- タブとカードを実際に押し、切り替えと詳細が動くことを確かめます。
- 裏側の定期実行（再構築）が有効なままであることを確かめます。作り直しの過程で無効化されることがあります。
- 検証環境で再現しない実機だけの描画は「再現しなかった」と書き、原因になりうる要素を除いたうえで実機の目視を本人に頼みます。
