# モデルの割り当てと切替

詳しくは https://github.com/aoaibiz/muse-opencode-go-kit/blob/main/docs/MODEL-SWAP.md にあります。要点は次のとおりです。

## 割り当て

- 作業の種類（実装・調査・設計と最終判断・レビュー）ごとにモデルを割り当て、表に残します（例：https://github.com/aoaibiz/muse-opencode-go-kit/blob/main/templates/model-routing.example.md）。
- 既定は安価なモデルです。上位モデルへの切り替え条件（検証の失敗回数、設計判断が必要な場面）を先に決めます。再試行と切り替えの回数には上限を設けます。
- レビュー担当は実装担当と別のモデルにします。

## エイリアスの罠

- 上位・中位・下位といった別名（エイリアス）で指定しても、接続先の設定で全て同じ実モデルへ解決されることがあります。その場合、レビューは独立になりません。
- 切替の後は必ず試し呼びを行い、画面（ペイン）や応答で**実際に動いたモデル名**を確認します。記録には別名ではなく実モデル名を書きます。

## 切替の手順

- ハーネス（実行の枠組み）は替えません。替えるのはモデルだけです。
- モデルの指定は、環境変数の組（接続先 URL、階層ごとのモデル対応、追加の設定）をプロファイルとしてファイルにまとめ、起動時に選ぶ形にします。プロファイルを増やせば、切替はファイルの選択に戻せます。
- モデルによっては提供側の地域設定などが前提になります。試し呼びのエラーに案内先が含まれる場合は、その設定を本人に案内します（設定の変更は本人の操作です）。
- 切替後に常時表示（端末のセッションが見える形）も同じプロファイルで起動するよう、起動の入口を1か所に揃えます。戻し方は「元のプロファイルで起動し直す」です。

## 逃げ道（フォールバック）

- 主経路が使えなくなった時だけ別モデルが動く形にします。条件（回数制限・認証切れ・障害・壊れた応答）と、戻り方（例：次の応答で主経路へ戻る）を先に決めて書きます。
- 実際に主経路の障害を起こしての確認ができない場合は、「未確認」と記録します。試し呼びの成功だけで切り替え全体を確認済みにしません。
