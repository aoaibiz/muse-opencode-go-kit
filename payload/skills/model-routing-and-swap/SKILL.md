# モデルの割り当てと切替

詳しくは https://github.com/aoaibiz/muse-opencode-go-kit/blob/d2e6bd388007527c1fe34e03fe0a05c7c5773a28/docs/MODEL-SWAP.md にあります。要点は次のとおりです。

## 割り当て

- 作業の種類（実装・調査・設計と最終判断・レビュー）ごとにモデルを割り当て、表に残します（例：https://github.com/aoaibiz/muse-opencode-go-kit/blob/d2e6bd388007527c1fe34e03fe0a05c7c5773a28/templates/model-routing.example.md）。
- 既定は安価なモデルです。上位モデルへの切り替え条件（検証の失敗回数、設計判断が必要な場面）を先に決めます。再試行と切り替えの回数には上限を設けます。
- レビューは実装と別の文脈で行います。独立性が要るレビュー（公開前の最終判定など）では別の実モデルを使い、それ以外は既定モデルの別文脈でも構いません。その区別を記録に書きます。

## エイリアスの罠

- 上位・中位・下位といった別名（エイリアス）で指定しても、接続先の設定で全て同じ実モデルへ解決されることがあります。その場合、レビューは独立になりません。
- 切替の後は必ず試し呼びを行い、画面（ペイン）や応答で**実際に動いたモデル名**を確認します。記録には別名ではなく実モデル名を書きます。

## 切替の手順

- ハーネス（実行の枠組み）は替えません。替えるのはモデルだけです。
- モデルの指定は、環境変数の組（接続先 URL、階層ごとのモデル対応、追加の設定）をプロファイルとしてファイルにまとめ、起動時に選ぶ形にします。プロファイルを増やせば、切替はファイルの選択に戻せます。
- モデルによっては提供側の地域設定などが前提になります。試し呼びのエラーに案内先が含まれる場合は、その設定を本人に案内します（設定の変更は本人の操作です）。
- 切替後に常時表示（端末のセッションが見える形）も同じプロファイルで起動するよう、起動の入口を1か所に揃えます。戻し方は「元のプロファイルで起動し直す」です。

## 運用の型（ベストプラクティス）

- 既定は安価な高速モデルに置き、難しい判断の時だけ、その1件を1段だけ上げます。セッション全体は上げません。
- 学習利用を条件とするモデルは、非公開情報や顧客・会員の情報を扱う仕事の既定にしません（格上げ先・レビュー・逃げ道に使うモデルにも、同じ条件を適用します）。
- 枠の運転：週7割・月6割までを通常運転とし、5時間枠が8割を超えたら新しい重い仕事を始めません。枠を増やすためにアカウントを足しません。
- 一部のモデルは平日の 10:00〜13:00 と 15:00〜19:00 に時間帯の倍率（2倍）が付きます。重いバッチはその時間帯の外へ寄せます。
- プラン（月10ドル／40ドル）の判断は、数日分の実測の消費が揃ってからにします。

## 逃げ道（フォールバック）

- 主経路が使えなくなった時だけ別モデルが動く形にします。条件（回数制限・認証切れ・障害・壊れた応答）と、戻り方（例：次の応答で主経路へ戻る）を先に決めて書きます。
- 実際に主経路の障害を起こしての確認ができない場合は、「未確認」と記録します。試し呼びの成功だけで切り替え全体を確認済みにしません。
