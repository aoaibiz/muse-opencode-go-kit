# Muse Window × OpenCode Go Kit

**「窓口」は無料の Muse、実行は自分の PC のエージェント。追加の LLM 契約は月10ドルから。**

会話・壁打ち（考えを整理する相談）・指示出し・結果の回収と報告は Muse の無料枠が担い、ファイル編集やコマンド実行などの実作業は、SSH でつないだ自分の PC 上のエージェント（Claude Code などのハーネス＝PC 上で作業を実行する仕組み）が、OpenCode Go のモデルを使って行う構成を、導入手順ごと公開したキットです。

タルムードの運用実績から、他の環境でも使える内容を新しく書き起こしました。企業固有情報・認証情報・接続先の実アドレスは含みません。

## 使い始める

Muse（またはファイルとコマンドを扱える AI エージェント）に、次の一文を送ってください。

> https://github.com/aoaibiz/muse-opencode-go-kit を私の環境に導入してください。README と INSTALL.md を読み、既存設定を保護して、導入と確認まで進めてください。

導入作業は AI が担当します。人間がターミナルを操作したり、コマンドを転記したりする必要はありません。人間の作業は最小限で、アカウントの登録・ログイン、許可のボタンを押すこと、自分の端末での最終確認だけです（[INSTALL.md](INSTALL.md) に箇所を明記しています）。

標準の導入範囲は、常時起動できる PC 1台です。URL だけを貼った場合も、AI はこのページを入口として扱い、導入先が明らかな時に進めます。導入の意図や対象が不明なら、AI が短く確認します。通常のチャットへ URL を貼るだけで、端末へ自動で導入されるものではありません。

必要なもの：Muse のアカウント（無料枠で開始できます）、常時起動できる PC（Mac / Windows / Linux）、その PC で動くコーディングエージェントのハーネス（Claude Code など）、OpenCode Go の契約（月10ドルが基本候補）、PC への SSH 接続手段（Tailscale など）。

## 構成

| 担当 | 仕事 |
|---|---|
| Muse（窓口） | 壁打ち、目的と条件の整理、実行依頼、結果の回収と説明 |
| PC 上のハーネスと OpenCode Go のモデル | ファイルの読み書き、コマンド実行、検証と、その推論 |

各担当の詳しい役割は [構成の詳細](docs/ARCHITECTURE.md) を参照してください。

窓口と実行を分ける理由は2つあります。会話と整理は無料枠で賄えるため、課金が「実行の推論」だけに寄ること。そして、スマホからでも PC からでも、同じ窓口・同じ実行基盤を使えることです。スマホ自体に SSH クライアントや実行環境を入れる必要はありません。

## コストの考え方

- 窓口（Muse）は無料枠が基本です。無料枠にも週の上限があり、無制限ではありません。上限に当たったら、枠の更新を待つか、必要になってから有料化を検討します。先に契約しないのが原則です。
- 実行（OpenCode Go）は月10ドルが基本候補です。Go は共通枠で、5時間・週・月の上限があります。月額だけで収める方針なら Extra Usage をオフにします。
- モデルによって「料金に対して得られる枠」は大きく変わります。例えば DeepSeek V4.1 Flash 1017 では、月10ドルで月100ドル相当の利用枠、月40ドル（Go Plus）で月200ドル相当です。料金4倍で枠は2倍なので、枠の単価では月10ドルの方が割が良い計算です。ただし足りるかどうかは実測の消費で判断します。他のモデルでは比率が違うため、自分が使うモデルで計算してください（2026-11-18 時点の公式表に基づきます。出典は [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)）。
- 「月10ドルで必ず足りる」とは言いません。エージェントの実行は1依頼で何度もモデルを呼ぶため、チャットの回数では見積もれません。実際の仕事単位で消費を記録し、足りなければ40ドルへの増枠を検討します。

## モデル選択の原則

既定は安価なモデル、上位モデルは難しい設計・最終判断・検証だけに使います。レビューは実装と別のモデルで行い、実際に動いたモデル名を記録します（原則は [設計方針](docs/PRINCIPLES.md)、割り当ての例は [モデル振り分けの例](templates/model-routing.example.md)）。

## 運用の型（実績から）

- 仕事の受け渡しは「受付 → 実行 → 結果の回収」が追える形にします。長時間の作業は接続が切れても PC 側で継続し、完了はイベントで知らせます。定期的な見回りに依存しません。
- 状態を見る画面（ダッシュボード）を作る場合は、更新は自動だけにし、手動の更新ボタンは付けません。表示する時刻は、そのデータが実際に保存された時刻です。全項目に実在の行き先へのリンクを持たせます。
- 「完了」の報告は、本番（利用者が実際に開く画面・実データ）で自分が確かめてからにします。作り手の環境での確認は、本番の代わりになりません。

## 導入後

窓口の Muse に普段どおり仕事を依頼してください。例えば：

> この不具合を直してください。完成条件を決め、PC 側で実装と検証を行い、本番で確認した結果だけを報告してください。

## 更新・取り消し

- 更新：「Muse Window × OpenCode Go Kit の更新内容を確認して、私の環境へ適用してください」
- 取り消し：「このキットの導入を取り消して、導入前に戻してください」
- 失敗時：「導入の診断結果を調べて、既存設定を守って復旧してください」

## 開発・公開

このキット自体の保守と公開の進め方は [保守と公開](docs/MAINTAINING.md) にあります。公開前の検査は `python3 scripts/check_release.py`（チェックサム、リンク、混入パターン、メタデータ、許可リスト）と `python3 -m unittest discover -s tests -v` で行います。

## 対応と限界

- 対象は、常時稼働の PC が1台ある個人・小規模チームです。payload の導入範囲は1つの作業フォルダー（プロジェクト単位）であり、端末全体への一括導入（利用者全体のスコープ）は未対応です。
- 受付、ランチャー、利用量の収集器などの運用部品そのものは、このキットには含まれません。それらの設計と手順を文書で示し、実装は各環境のエージェントが行います。
- このキットは、アカウントの契約・鍵の登録・料金の支払いを代行しません。本人の操作が必要な箇所は [INSTALL.md](INSTALL.md) に明記しています。
- 料金・枠・対応モデルは変わります。本書の数字は 2026-11-18 時点の公式情報に基づく参考値で、契約前に公式ページで再確認してください。
- 実行量が増えれば、窓口を無料にしても実行側の必要枠は減りません。コストの効果は「会話を窓口へ寄せた分」だけです。
- 会社や個人の情報管理・承認の決まりが、このキットの手順より優先します。
