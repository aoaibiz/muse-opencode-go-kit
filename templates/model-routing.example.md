# モデル振り分けの例

作業の種類ごとに使うモデルの割り当て例です。モデル名は一例で、契約しているプランで使える物に置き換えてください。大事なのは「既定は安価なモデル」「レビューは別のモデル」「実モデル名で記録する」の3点です。

| 作業の種類 | 既定のモデル | 切り替え条件 |
|---|---|---|
| 実装（通常） | 安価な高速モデル（例：DeepSeek V4.1 Flash 1017） | 検証に2回失敗したら上位モデルへ |
| 調査・読み込み | 安価な高速モデル | 判断が割れる論点だけ上位モデルへ |
| 設計・最終判断 | 上位モデル（例：DeepSeek V4 Pro） | ― |
| レビュー（検品） | 実装と別のモデル | 別名ではなく実モデルで別にする |
| 窓口（会話・整理・報告） | Muse の無料枠（Muse Spark） | 無料枠の上限に当たったら待つ／有料化を検討 |

## 記録の注意

- エイリアス（opus / sonnet など）で指定しても、接続先の設定で同じ実モデルへ解決されることがあります。実呼び出しで解決先を確認し、記録には実モデル名を書きます。
- 逃げ道（フォールバック）を使う場合は、切り替えの条件（回数制限・認証切れ・障害・壊れた応答など）と戻り方（次の応答で既定へ戻る等）を先に書きます。
