# 検証記録

対象：0.1.1、2026-11-18。私たちの運用環境（窓口＝Muse 無料枠、実行＝Mac と Windows の PC 各1台）での実績です。顧客データ・実在の接続先・認証情報は含みません。

## 書き方

- 項目ごとに「設定が入っていること」「実際の挙動で確かめたこと」「未確認であること」を分けて書きます。
- 件数を言う時は、母数（全体の実数）と使った検査を添えます。「異常なし」は、検査の範囲が分かる形でのみ書きます。
- 測れなかった物は「未測定」と書きます。見込みや計算で代用しません。
- 画面の完成は、実描画の確認と実操作（押す・開く・戻る）の結果を証拠にします。数値の自己申告は証拠にしません。

## 確認済み

- **接続**：2台の PC へプライベートネットワーク経由で接続し、相手のマシン名と利用者名が想定どおりであることを確認。公開鍵の登録まで完了。実行環境の再配置でホスト鍵の記録が消えて接続が止まる事故があり、記録の保存先を永続化される場所へ移して復旧した。
- **往復と通知**：受付経由の依頼 → 実行 → 結果の回収を通した。完了通知は合図ファイルの行単位の検知にし、同じ受付番号への追記も新しい到着として扱う。番号単位の判定で追記3件を見逃した事故を、行単位への修正とドライラン、その後の実発生で確認した。
- **ダッシュボード**：本番の実データを読み戻し、件数・中身・更新時刻の前進を確認。はみ出し・切れ・横スクロールが0であることの実測はスマホ幅（390）と PC 幅（1440）で実施（他幅は CSS の計算で確認した範囲であり、実測とは書かない）。タブ切り替えと詳細表示を実際に押して確認した。
- **残量表示**：端末の表示で、時間をあけて2回流し、短期の枠（5時間）の数字が実際に進むことを確認。採取時刻が一定間隔で進むことも確認した。
- **モデル切替**：プロファイル方式で頭のモデルを切り替え、隔離した試し呼びと画面表示で、実際に動いたモデル名を確認した。別名（上位・中位・下位）が全て同じ実モデルへ解決されていた事実を発見し、記録は実モデル名で書くよう改めた。
- **このキット**：installer と公開検査の自動試験26件（導入、既存バイト列の保持、重複実行、検証、復元、復元時の後編集の保護、手編集の競合、チェックサム不一致、途中状態からの復旧、ファイルモードの保持、バックアップの権限保持、異常な状態記録、ロック、リンク拒否（配置先・親・状態フォルダー・バックアップ・復元時）、manifest のパス検証、公開検査の形式によらない検出ほか）と、公開検査（チェックサム、リンク、混入パターン、メタデータ、許可リスト）が合格。初版の公開コミットは `c3801b271fc462eaee9fa6e2916c7c33be94c635`。公開後、公開ページから README を読み戻して内容の一致を確認した。作り手と別の担当による対照レビュー（参照キットとの同等性と公開安全）で、重大1件（復元の無条件上書き）を含む指摘を受け、全件を修正して再試験した。
- **再監査への対応（0.3.1、2026-11-19）**：0.3.0 の公開後、作り手と別の担当による再現ベースの再監査を受けた。前回の4件のうち3件（リンク経由の対象外書き込み、復元時の対象外削除、拡張子による検査除外）は元の再現条件が止まることを確認された。残りと追加の指摘に対応した。(1) SEC-01 の更新経路：旧版が作った状態フォルダー（0755）とバックアップ（0644）の権限が、新版を適用しても直らなかった → apply の時に境界検査を通したうえで、フォルダーは 0700、ファイルは 0600 へ移す修復処理を追加。旧版の状態を再現する回帰テストで、修復後に verify と rollback が引き続き動くことまで確認した。(2) OPS-01：バックアップ先のリンク拒否がロック解放より前にあり、拒否の後にロックが残って再実行が LOCKED で失敗した → ロック取得後の全処理を同じ try/finally の内側へ移した。拒否後にロックが残らず、原因を除いた再実行が成功する回帰テストを追加。(3) SEC-05：verify が AGENTS.md だけリンク検査をしていなかった → 読み込み前に同じ境界検査を適用。(4) SEC-06：公開検査が UTF-16 のファイルで秘密パターンを検出しなかった → BOM で判定できる UTF-16 を通常の文字列へ直して同じパターンで検査し、UTF-16LE／BE の回帰テストを追加。あわせて、Git worktree で `.git` がファイルになる場合の検査の誤判定を解消し、`.gitignore` 追加だけでは追跡済みファイルは外れない旨を INSTALL に明記した。文書面では、レビューのモデルの規則が文書間で食い違っていた点を統一した（レビューは別の文脈で行い、独立性が要る場合だけ別の実モデルを使う。その区別を記録する）。データ条件（学習利用モデルを使わない）は、既定だけでなく格上げ先・レビュー・逃げ道にも適用すると明記した。自動試験は 32 件（新規6件を含む）に増え、全件合格。公開検査も合格。

## 公開前に修正した問題

- 保存側の形式チェックが厳しすぎて、正しい更新が無言で弾かれ、画面が古いまま固まった。保存時に整形・吸収する形へ直し、保存後は更新時刻の前進で確認するよう改めた。
- 作り手のテスト用複製だけにデータが入り、本番が空のまま「完了」と報告した。本番の実データを自分で読み戻してから報告する手順に改めた。
- 裏側の定期実行が作り直しの過程で無効化され、表示の時刻が止まった。再有効化し、完成確認の項目へ「定期実行が有効か」を加えた。
- 題に埋め込んだ絵文字とアイコン欄で、画面に絵文字が2個並んだ。絵文字はアイコン欄だけに持ち、題からは保存時と表示時の両方で取り除くよう改めた。
- 演出のグローの中心が画面端に乗り、実機で端に縦線が出た。中心を内側へ移した。この事象は検証環境（Chromium）では再現しなかったため、実機の目視確認を別途行った。
