# 検証記録

導入と運用で「何を・どう確かめたか」を残すための型です。記録は、確かめた事実だけを書きます。

## 書き方

- 項目ごとに「設定が入っていること」「実際の挙動で確かめたこと」「未確認であること」を分けて書きます。
- 件数を言う時は、母数（全体の実数）と使った検査を添えます。「異常なし」は、検査の範囲が分かる形でのみ書きます。
- 測れなかった物は「未測定」と書きます。見込みや計算で代用しません。
- 画面の完成は、実描画の確認と実操作（押す・開く・戻る）の結果を証拠にします。数値の自己申告は証拠にしません。

## 導入時の確認項目（例）

| 項目 | 確かめ方 | 記録の例 |
|---|---|---|
| 接続 | 窓口から PC へ接続し、相手のマシン名と利用者名を読む | 疎通済み／相手は想定どおり |
| 往復 | 小さい依頼を1件通し、受付番号と結果の回収まで追う | 受付→実行→回収まで実績あり |
| モデル | 試し呼びを行い、実際に動いたモデル名を記録する | 実モデル名を記録済み |
| 利用量 | 窓口側と Go 側の両方の表示を読む | 両方とも表示あり／時点を併記 |
| 通知 | 完了の合図がイベントで窓口へ届くか | 合図から回収まで実績あり |
| 復旧 | 接続が切れた状態から、作業が継続・回収できるか | 未確認 |

## 運用時の確認（確かめ役）

実行側が本番へ変更を入れた時は、窓口側が独立に確かめる役を担います。

- 確かめる内容・場所・合格の線は、変更の前に受け取ります。
- 結果は「確かめ ＜名前＞: OK」または「NG= ＜見えた事＞」の一行で返します。
- 作った側の検証結果は、そのまま合格にしません。本番の実物で確かめます。
