# 記憶の整理（本体の圧縮とシーン別分割）

窓口エージェントの長期記憶は、放っておくと1ファイルに全部が積み上がり、着手のたびに全文を読む形になってしまいます。私たちが実際に使っている整理の型です。

## 形

- **本体（MEMORY.md）には2つだけ**を置きます。
  1. **超重要事項**：利用者の名前と呼び方、エージェントの役割、報告の絶対ルール、本人の直接の言葉が要る事項（金銭、外部への送信、削除、秘密情報）など、どの仕事でも外せない数行。
  2. **シーン別ファイルへの目次**：ファイルの置き場所と「いつ読むか」を1行ずつ。
- **詳細はシーン別ファイルへ分割**します（置き場所の例：`~/memory/scenes/`）。用途ごとに1ファイルにし、先頭に「読む時：〜の開始時」と書きます。分け方の例：仕事の進め方と好みのルール、運用中のサービス、実行マシンと相手エージェント、クライアント運用、個人の連絡、画面とボード、サイトと公開物。
- **運用ルール側（AGENTS.md）に1行**を足します：「タスク開始時、目次を見て、該当シーンのファイルを読んでから着手します。」

目次の行の例（形式の見本です）：

```markdown
- `~/memory/scenes/work-rules.md` — 仕事の進め方・好みのルール集。読む時：あらゆる成果物・報告・依頼の仕事の開始時。
- `~/memory/scenes/clients.md` — クライアント運用の入口。読む時：クライアント対応の開始時。ここから台帳を引く。
```

## 手順

1. 分割前に、本体の全文をバックアップへ保存します（置き場所の例：`~/workspace/memory-backup-YYYYMMDD/`）。戻せる状態にしてから動きます。
2. 本体の内容を用途ごとに振り分け、シーン別ファイルへ移します。移す時に要約し直さず、まず原文のまま用途別に寄せます（要約は情報の欠落の元です）。
3. 本体を「超重要事項＋目次」だけに書き直します。目次の各行に、パスと「いつ読むか」を必ず書きます。
4. 検証：元の本体にあった固有の語（名前、決まり、数値）を数十個選び、全てが「本体の超重要事項」か「いずれかのシーン別ファイル」のどちらかに残っていることを機械的に確かめます。残っていない語があれば、移し漏れとして戻します。

## なぜこの形か

- 着手時に読む量が、その仕事に要る分だけになります。全文読みは速くなりますが、それ以上に「関係ない文脈を持ち込まない」効果があります。
- 超重要事項だけは常時見える場所に残るので、分割しても絶対ルールが埋もれません。
- 目次に「いつ読むか」が書いてあると、エージェントが自分で判断して読みに行けます。「全部読め」でも「読むな」でもない形です。

## 保守

- 新しい用途が増えたら、シーン別ファイルを1つ足し、目次に1行足します。本体へ詳細を書き戻しません。
- 古くなった記述は、そのシーン別ファイルの中で直します。本体とファイルで同じ事実が食い違ったら、新しい利用者の指示と新しい記録が勝ちます。
- 定期的に（例：週1回）重複と古い記述を寄せる整理をし、変わった時だけ短く報告します。
