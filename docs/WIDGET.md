# 残量ウィジェットと端末表示の作り方

AI の残量（利用枠）は、常に・その場で・正しい数字が読めることが要件です。「読めていない」を許容しない、が原則です。

## 表示する場所

- **端末（ターミナル）のステータス表示**：実行側のセッションに常時表示します。
- **スマホのホーム画面ウィジェット**：持ち歩く端末で見るための表示です。
- どちらも**同じ実測値**を使います。場所ごとに別々に測ると、数字が食い違います（実際に起きた指摘）。

## 数字の取り方

- 利用量は、モデル提供側の応答に含まれる利用量の情報（消費量・枠・課金の出所）から取ります。応答に無い項目を、別の仕組みの値で代用しません（例：ある経路では送られてこない残量欄を読み続け、「取得待ち」のまま固まる事故がありました）。
- 読めない時は「取得待ち」ではなく「**読めていない**」と、理由つきで表示します。読める経路を別に用意することが解決であり、表示の文言を変えることは解決ではありません。
- 収集は短い間隔（例：毎分）で行い、値が変わったら表示側へ流します。費用の試し呼びのように単価のかかる確認だけは、間隔を分けます（例：15分）。

収集から表示への受け渡しの形式の例（値は一例です）：

```json
{
  "source": "opencode-go",
  "collected_at": "2026-01-01T09:00:00+09:00",
  "frames": {
    "5h": { "used_pct": 58, "resets_at": "2026-01-01T14:00:00+09:00" },
    "week": { "used_pct": 23, "resets_at": "2026-01-05T09:00:00+09:00" },
    "month": { "used_pct": 11, "resets_at": "2026-02-01T00:00:00+09:00" }
  },
  "cost_in_allowance": 0
}
```

端末の表示とウィジェットは、この同じ記録を読みます。表示ごとに別々に収集すると、数字が食い違います。

## ウィジェットの行の作り方

- **行の名前は、測っている物の名前**にします（例：OpenCode Go の枠を測る行は「OpenCode」）。動かしているエージェントの名前を行の名前にしません。
- **各行に、そのサービスのアイコン**を入れます。アイコンの無い行は未完成です。
- **デザインは全行で統一**します。行ごとに書体・色・余白が違うと、別の物に見えます。
- OpenCode Go のように複数の期間の枠がある場合は、**全期間を表示**します（例：5時間・週・月）。幅が足りない時は、落とす順番（短期→長期）を先に決めておきます。

## リアルタイムの確かめ方

「設定した」ではなく「数字が動いた」ことが証拠です。

1. 同じ表示を、時間をあけて（例：約2分）2回流します。
2. 消費が進むはずの枠（短期の枠）の数字が実際に進んだことを読みます。
3. 採取時刻が一定間隔で前へ進んでいることも併せて確かめます。

## 更新の届け方

- ウィジェットは押し出し（プッシュ）で更新される形にし、利用者が手で更新しなくてよいのが原則です。
- 仕組み上、包み（アプリ側のパッケージ）の置き換え直後などに、利用者の1回の操作（「今すぐ更新」）が必要になる場合は、そのタイミングだけを正確に伝えます。まだ置き換えが済んでいない段階で操作を求めません。
- ロック画面の常時表示（Live Activity など）は、仕組み上の時間上限と、開始した本人以外は更新できない制約を確かめてから採否を決めます。
