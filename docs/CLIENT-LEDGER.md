# クライアント台帳（案件ユーザーの置き場）

案件を持ってきた利用者（クライアント）が増えていく前提で、情報を溜めるための置き場の作り方です。私たちが実際に使っている型を一般化しました。

## 置き場所と形

- 置き場所の例：`~/memory/clients/`
- **台帳（INDEX.md）**：クライアントの一覧表。列は「クライアント／店舗・会社／サービス／状態／ファイル」。
- **1クライアント＝1ファイル**。全ファイルで項目の型をそろえます：
  - 会社・店舗
  - 担当者
  - 契約内容（金額などの条件は、確認できた範囲だけを書く。本人の発言が曖昧な場合は「未確認」と明記し、断定しない）
  - 使うサービス
  - 運用状態（いま何がどこまで進んでいるか）
  - 窓口・接続（連絡手段、相手側の実行役、同意済みの範囲）
  - 注意（やってはいけないこと、相手の都合）

## 分け方

- **「人」としての情報は人物ファイル側**（関係性、個人的な文脈）に残します。
- **「案件」としての情報はクライアント側**（契約、運用状態、窓口）に書きます。
- 人物ファイルの先頭に「案件の情報はクライアント台帳側」と1行の目印を付け、探す側が迷わないようにします。
- 記憶の目次（[記憶の整理](MEMORY-ORGANIZATION.md)）には「クライアント運用」のシーンを1つ置き、そこから台帳を引く形にします。クライアントが増えても目次は増えません。

## 運用

- 新しいクライアントが来たら、台帳に1行と、その人のファイルを1つ、同じ型で足すだけにします。置き場の設計をその都度変えません。
- 状態が変わったら、そのクライアントのファイルの「運用状態」だけを更新します。台帳の「状態」列も同じタイミングで合わせます。
- 終わった案件は消さず、状態を「終了」にして残します（後から同じ相手の別案件が来るため）。

型の実例は [クライアント台帳の例](../templates/client-ledger.example.md) にあります（名前と内容は架空の例です）。
