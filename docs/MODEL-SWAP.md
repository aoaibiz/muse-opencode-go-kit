# モデル切替（脳の交換）の実務

実行側エージェントの「脳」＝モデルだけを替え、ハーネス（実行の枠組み）は替えない、が前提です。ここでは OpenCode Go のモデルへ切り替える具体的な手順と、つまずきどころを書きます。

## 用語

- **脳**：モデルそのもの。
- **ハーネス**：Claude Code や Codex などの実行の枠組み。脳を替えても替えません。
- **プロファイル**：接続先とモデルの対応をまとめた設定ファイル。切替はプロファイルの選択です。

## プロファイルの形

プロファイルは環境変数の組です。階層（上位・中位・下位）ごとにモデルを割り当てます。下記は概念図です。変数名と接続先は、使うハーネスと提供側の公式ドキュメントにある実物へ置き換えてください（ハーネスごとに読み取る変数名が異なります）。

```text
# 接続先（提供側の窓口の URL）
<接続先の変数>=<接続先 URL>
# 階層ごとのモデル
<上位モデルの変数>=<上位モデル>
<中位モデルの変数>=<中位モデル>
<下位モデルの変数>=<下位モデル>
# 追加の設定（ツール検索の無効化、実験的機能の無効化など）
```

- 鍵はプロファイルに書かず、別ファイル（所有者だけが読める権限）に置き、起動時に読みます。
- 起動は小さなランチャーを介します：プロファイルを読み、鍵を読み、ハーネスを適切な引数で起動する。切替はランチャーへ渡すプロファイル名を変えるだけです。戻す時は元のプロファイル（または素の起動）に戻します。

## 切替の手順

1. 今のセッションの状態（作業中の引き継ぎ記録）を読み、止めてよいか確認します。本線の作業が走っている場合は、その所有者に確認してから止めます。本人の直接指示で引き継ぐ場合を除きます。
2. 新しいプロファイルで**隔離した試し呼び**を1回行い、応答が返ることと、実際に動いたモデル名を確認します。
3. セッションを新しいプロファイルで起動し直します。
4. 画面（ペイン）に表示されるモデル名が想定どおりか目で確かめます。
5. 常時表示の入口（利用者が端末で見るセッション）も、同じプロファイルで起動するよう直します。ここを直し忘れると、次に表示側から起動した時に元の脳へ戻ります。
6. 受付経由で短い依頼を1件通し、返事が戻ることを確かめます。

## つまずきどころ

- **地域設定**：モデルによっては、提供側コンソールの地域設定（例：Global）が前提で、未設定だと試し呼びがエラーになります。エラーの案内に設定画面の場所が含まれることがあります。設定の変更は本人の操作です。
- **エイリアスの解決**：上位・中位・下位の別名が、全て同じ実モデルへ解決されることがあります。「別モデルでレビューした」ことにはならないので、記録は実モデル名で書きます。プロファイルを作る時は、階層ごとに本当に別のモデルを割り当てたか、試し呼びで確認します。
- **提供側の保証範囲**：ハーネスとモデルの組み合わせによっては、提供側が公式に対応外とする経路もあります。変換や接続の保証がどちらの側にあるかを、契約前に公式情報で確認します。
- **サブスクリプション連動の機能**：窓口側の契約に連動する機能（成果物の共有、遠隔操作、連携コネクター、定期実行など）は、別経路の鍵では動かなくなることがあります。切替前に影響を洗い出します。
- **表示の取り違え**：セッションを裏側で起動し直すと、利用者の端末に表示されなくなります。表示の付け直しは対話セッション経由で行います（`docs/INTAKE.md` 参照）。

## 逃げ道（フォールバック）の設定

- 主経路が使えなくなった時だけ、別モデルが1回の応答単位で動き、次は主経路へ戻る形にします。
- 条件は先に決めます：回数制限、認証切れ、サーバー障害、壊れた応答。
- 鍵は直書きせず、秘密の保管場所を参照する形にします。
- 主経路の障害を実際に起こしての確認ができない場合は、その旨を「未確認」と記録します。

## 実測で比べる（宿題の型）

モデルの優劣は、単価と公開ベンチマークだけでは決められません。同じ仕事を割り当て、仕事の種類ごとに次を測って比べます。

- 完成率（1回で合格した割合）
- 手戻りの回数
- 完成した1件あたりの枠の消費

測っていない段階では「コスパが良い」と断定しません。
