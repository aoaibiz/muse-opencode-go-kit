# OpenCode Go のモデル運用ベストプラクティス

OpenCode Go のモデルを実務で回すときの、私たちの実測と調査から固めた運用の型です。料金と枠の数字は 2026-11-18 時点の公式情報に基づきます（出典は末尾）。モデルや料金は変わるので、判断の前に公式で再確認してください。

## 既定モデルと格上げ

- **既定は安価な高速モデル**（私たちの実測では DeepSeek V4.1 Flash 級）に置き、通常の開発・運用のほぼ全てをそれで回します。安いモデルでも、仕事を完了するまでの総消費で見れば十分に合理的でした。
- **難しい判断の時だけ、その1件を1段だけ上げます**（候補は同系列の上位モデルなど）。セッション全体を上位に上げることはしません。上げるのは「判断」であって「作業全体」ではない、が線引きです。
- レビューや最終判定も通常は既定モデルのままにします（作った側とは別の文脈で行います）。独立性が要るレビュー（公開前の最終判定など）でだけ、別の実モデルを指定して呼びます。既定モデルの別文脈で見た場合は「同モデル・別文脈」と記録し、別のモデルで確かめたことにしません。

## 別名（エイリアス）で指定しない

- モデルは**必ず実モデル名で指定**します。上位・中位・下位といった別名は、接続先の設定で全て同じ実モデルへ解決されることがあります。私たちは実際にそれを踏み、「別のモデルで検品した」つもりが同じモデルだった、という記録違いを起こしました。
- レビューや検証の記録には、実際に動いた実モデル名を書きます。別名のまま記録しません。

## データ条件で使わないモデル

- **学習利用を条件とするモデル（contributor 型など）は、非公開の情報・顧客や会員の情報を扱う仕事の既定にしません。** 安さと引き換えに入力・出力が将来の学習に使われる条件が付いているためです。料金の安さだけで選ばない、が原則です。この条件は既定モデルだけでなく、格上げ先・レビュー・逃げ道に使うモデルにも同じく適用します（既定だけ安全、を防ぐためです）。
- 無料モデルにも、日次上限、利用クライアントの制限、地域設定などの条件があります。一覧に載っていることは、今の構成でそのまま使えることの保証ではありません。

## 枠（利用量）の運転

枠は 5時間・週・月の3つが同時に効きます。私たちの運転の目安です。

- **週は7割、月は6割までを通常運転**とします。それを超えたら、締めの仕事だけに切り替えます。
- **5時間枠が8割を超えたら、新しい重い仕事を始めません。**
- 枠が尽きた時の順番：①重い仕事を止めて軽い仕事だけにする、②5時間枠の回復を待つ、③今日中に終わらせる必要がある判断だけ、枠消費の小さいモデルへ1件逃がす。**枠を増やすためにアカウントや回線を足しません。**
- プランの判断は実測でします。数日分の実際の使用率（期間別）とモデル配分が揃うまで、増枠も減額も決めません。

## プランの選び方（10ドルと40ドル）

OpenCode Go には月10ドルと月40ドル（Go Plus）があります。**どちらが良いかは、その人の実測の消費次第です。**

- 10ドルが基本候補です。まず10ドルで始め、実際の仕事単位の消費を記録します。
- 参考の計算（2026-11-18 の公式表）：私たちが使う高速モデル（DeepSeek V4.1 Flash）では、10ドルで月100ドル相当、40ドルで月200ドル相当の利用枠でした。料金は4倍で枠は2倍なので、枠の単価では10ドルの方が割が良い計算です。ただし枠が実際に足りなくなるなら、40ドルへ上げる意味があります。他のモデルでは比率が違うため、自分が使うモデルで計算してください。
- 月額だけで収める方針なら、枠超過の従量（Extra Usage）はオフにします。

## 時間帯料金

- 一部のモデルには時間帯の倍率があります。私たちの実測では、DeepSeek の2モデルで**平日の日本時間10:00〜13:00と15:00〜19:00が2倍**、それ以外は基準単価でした（Go 自身の料金設定で確認。祝日の例外は Go の設定にはありませんでした）。
- 重いバッチ仕事は、この時間帯の外へ寄せると半額になります。逆に、消費が「最初は速く、途中から安く感じる」時は、単価の変化と5時間枠の更新が重なっている場合があります。枠の更新は消費効率の改善ではないので、混同しません。

## キャッシュとセッションの組み方

- 同じ入力の再利用（キャッシュ）が効くと、その部分は安い読取単価になります。読取単価の割引幅はモデルで大きく違います（通常入力の 1/4〜1/120）。
- ただし**キャッシュの安さだけでモデルを選ばない**こと。元の入力・出力の単価、月枠の相当額、長文の加算条件まで合わせて見ます。読取が極端に安いモデルでも、試算では月枠の消費が数倍になる例がありました。
- 組み方：同じ仕事は同じセッションで続け、共通の指示や資料の並びをむやみに変えません。別の仕事は別のセッションに分けます。毎回全資料を読み直す構成は、再利用を弱めます。
- 実作業のキャッシュ率は環境によって測れる範囲が限られます。測れていない効果を「効いている」とは書かず、未測定として残します。

## 比較の物差し

- モデル比較は「1応答の安さ」ではなく、**同じ課題を完了するまでの総消費**（入力・出力・再試行・修正回数・時間）で比べます。高いモデルでも手戻りが減れば総消費が下がり、安いモデルでも失敗を繰り返せば逆転します。
- 料金表の順位を、そのまま能力の順位として扱いません。品質・速度は別に測ります。
