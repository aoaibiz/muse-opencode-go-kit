# ダッシュボードの作り方

窓口（Muse）で作る「状態を見る画面」の具体的な作り方です。私たちが実際に作り、実機で却下され、直した経緯を一般化してあります。

## 全体の形（3階層）

1. **最初の画面**：スクロールなしで収まるメニュー（カテゴリの一覧）。1画面に収まらない時点で設計を疑います。
2. **カテゴリの中**：絵文字アイコンつきのカード一覧。
3. **詳細**：カードをタップすると、その項目の詳細が開く。

縦に長い1枚ページ（全部を積み上げる形）は却下された形です。状態の区分（要対応／進行中／完了など）も、縦に積まず**タブの切り替え**にします。タブを押すと、その区分だけが表示されます。件数の少ない区分はスクロールなしで1画面に収まるのが合格の線です。

## データの形

画面は「データ」と「表示」を分けます。データは次のような構造の JSON で持ちます（例は一般化したものです）。

```json
{
  "updatedAt": "2026-01-01T09:00:00+09:00",
  "categories": [
    {
      "id": "board",
      "title": "依頼ボード",
      "icon": "📋",
      "items": [
        {
          "title": "項目の題",
          "icon": "📝",
          "status": "waiting",
          "summary": "1行の要約",
          "detail": "詳しい内容",
          "url": "https://example.com/real-destination"
        }
      ]
    }
  ]
}
```

- `status` は区分のキーです（例：`waiting`＝要対応、`active`＝進行中、`done`＝完了、`other`＝その他）。表示側はこのキーでタブに振り分け、タブに件数を出します。
- `icon` はカテゴリと項目の絵文字を入れる**唯一の場所**です。`title` に絵文字を埋め込むと、画面で絵文字が2個並びます（実際に起きた却下理由）。保存時と表示時の両方で、題から絵文字を取り除く処理を入れます。
- `url` は実在の行き先だけです。推測で URL を作りません。行き先が無い項目は、リンクなしを明示します。

## 最新化の仕組み

- **保存は寛容に**：保存側の形式チェックが厳しすぎると、正しい更新が無言で弾かれ、画面が古いまま固まります（実際に起きた事故）。保存時に整形・吸収し、保存できたかを `updatedAt` の前進で必ず確認します。
- **定期の再構築**：裏側の定期実行（例：15分ごと）が元データから画面データを再構築します。この定期実行が無効化されていないかを、完成確認の項目に入れます。止まっていれば画面の時刻が止まります。
- **画面の自動再読込**：開いている間は短い間隔（例：30秒）でデータを読み直します。手動の更新ボタンは付けません。押しても終わらないボタンは最悪の使い勝手として作らない、が決まりです。
- **表示する時刻**：`updatedAt`（そのデータが実際に保存された時刻）をそのまま表示します。「今の時刻」を表示すると、データが古くても新しく見えてしまいます。

## 見た目の型

- 差し色は1つだけにします。状態の違いは色相ではなく、形と文字のラベルで分けます。
- カードは「状態と担当の1行 → 題 → 要約」の3段にします。
- 日本語の折り返し：本文には `line-break: strict` と `word-break: auto-phrase`、見出しには `text-wrap: balance`、本文には `text-wrap: pretty` を指定し、行頭禁則と孤立行が出ないようにします。長い名前や文は省略（…）で切らず、折り返して全文を見せます。
- 演出（光・グロー・動き）は文字の背面だけに置き、文字は最初から読める状態にします。**グローなどの中心は画面の内側に置きます**。中心が画面端や画面外に乗ると、実機で端に縦線・帯が出ます（実際に起きた不具合）。
- 広い画面では、読む列の幅を約680pxに抑え、余白で整えます。スマホ幅と PC 幅で別の崩れ方が起きるため、両方で測ります。

## 完成の確かめ方

数値の自己申告ではなく、実描画と実操作が証拠です。

1. 本番のデータを読み、件数・中身・`updatedAt` が想定どおりか確かめる（作り手のテスト用コピーでの確認は本番の代わりになりません。実際に、本番だけ空だった事故がありました）。
2. スマホ幅（390）と PC 幅（1024／1280／1440）で描画し、はみ出し・切れ・重なり・横スクロールが0であることを測る。
3. タブやカードを実際に押し、切り替えと詳細表示が動くことを確かめる。区分が少ないタブでは内側のスクロール量が0であることも測る。
4. 一番長い実データ（一番長い題・要約）で測る。短い見本で測ると本番で崩れます。
5. 定期実行が有効であることを確かめる。
6. 検証環境で再現しない実機だけの描画（端末固有の描画エンジンの差）は、「再現しなかった」と正直に書き、原因になりうる要素を取り除いたうえで、実機での目視を本人に頼みます。再現しなかった物を「確認済み」とは言いません。
